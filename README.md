# Site Scanner 3D (สแกนหน้างาน 3D)

แอป Android สำหรับ**สแกนพื้นที่หน้างานเป็น 3 มิติ** แล้วนำขนาดไปทำ **Shop Drawing**
ใช้ ARCore (Depth API) ของ Google สแกนห้อง/พื้นที่จริงเป็น point cloud, วัดระยะด้วย AR,
สร้างแปลนพื้น (floor plan) พร้อมเส้นบอกขนาดอัตโนมัติ และส่งออกไฟล์ไปเปิดใน AutoCAD / Revit / SketchUp

> สถานะ: **v0.1 (โครงเริ่มต้น)** ใช้งานได้ครบวงจร สแกน → ดู 3D → แปลน → ส่งออก
> แต่ยังต้องทดสอบภาคสนามบนมือถือจริง ดู [แผนพัฒนาต่อ](#แผนพัฒนาต่อ-roadmap)

## ความสามารถ

| ส่วน | รายละเอียด |
|---|---|
| **โปรเจกต์** | แยกตามหน้างาน (ชื่อ, สถานที่, หมายเหตุ) แต่ละโปรเจกต์มีได้หลายสแกน |
| **ปักหมุดหน้างาน** | สร้างโปรเจกต์ใหม่แล้วปักหมุดตำแหน่งปัจจุบันจาก GPS ให้อัตโนมัติ พร้อมเติมที่อยู่ให้ หรือเลือกจุดเองบนแผนที่ OpenStreetMap (ลาก/แตะ/ค้นหาที่อยู่ ต้องต่ออินเทอร์เน็ต) กดเปิดหมุดในแอปแผนที่ได้ พิกัดติดไปในหัวแบบ DXF ด้วย |
| **ภาพถ่าย & วิดีโอ** | ถ่ายภาพหรืออัดวิดีโอหน้างานด้วยแอปกล้องของเครื่อง หรือนำเข้าจากแกลเลอรี เก็บไว้ในโปรเจกต์คู่กับสแกน (โฟลเดอร์ `media/` ชื่อไฟล์ `IMG_/VID_วันที่_เวลา`) แสดงเป็นตารางภาพย่อในหน้าโปรเจกต์ แตะเพื่อเปิดดูเต็มจอ กดค้าง (หรือเมนูมุมภาพ) เพื่อแชร์หรือลบ |
| **สแกน 3D** | รวมภาพ depth จาก ARCore Raw Depth เป็น point cloud สี (voxel 1 ซม., ถ่วงน้ำหนักตามความมั่นใจของ depth) — มือถือที่ไม่มี Depth API จะใช้ feature points แทน (ห่างกว่า) |
| **อัดวิดีโอ → สร้าง 3D** | ระหว่างสแกนแอปอัดภาพ ตำแหน่งกล้อง และ depth ของทุก keyframe ไว้ พอบันทึกจึงสร้าง point cloud และโมเดล 3D สีจริงจากวิดีโอนั้นด้วยทุกเฟรม (TSDF voxel 2 ซม. + surface nets, ตัดเศษลอย ๆ ทิ้ง) แล้วนำภาพถ่ายจริงจากเฟรมที่อัดไว้แปะลงบนผิวโมเดล (photo texture ซึ่งติดไปกับไฟล์ GLB ที่ส่งออกด้วย โดยปรับแสง/สีของแต่ละแผ่นภาพให้เท่ากันตรงรอยต่อ) สร้างใหม่ได้ทุกเมื่อ ส่งออกวิดีโอเป็น ZIP พร้อมไฟล์ตำแหน่งกล้องสำหรับ COLMAP / Postshot / nerfstudio และมี `reconstruct.jar` สำหรับสร้างบนคอม — โมเดลในเครื่องต้องใช้มือถือที่รองรับ ARCore Depth API |
| **วัดระยะ AR** | เล็งเป้ากลางจอ กด *วัดระยะ* 2 ครั้ง ได้ระยะจุดต่อจุดเป็น มม. (ยึดด้วย ARCore Anchor) ตั้งชื่อระยะได้ เช่น "ความกว้างประตู" |
| **ดู 3D** | หมุน/เลื่อน/ซูม point cloud, สลับสีจริง ↔ สีตามความสูง, แสดงเส้นระยะที่วัด |
| **แปลนพื้นอัตโนมัติ** | หาระดับพื้น-ฝ้า, ตัดระนาบแนวนอนผ่านผนัง, หาแนวผนังหลักแล้วหมุนให้ขนานแกน, สกัดผนัง (รวมผนังเฉียง), ต่อมุมให้ปิด, แสดงความยาวผนังเป็น มม. และความสูงพื้นถึงฝ้า |
| **ประตู / หน้าต่าง** | ตรวจจับประตู หน้าต่าง และช่องเปิดในผนังอัตโนมัติ ได้ความกว้าง สูง ขอบล่าง (sill) ขอบบน (head) และระยะห่างจากมุมผนัง ติด tag D1, W1… บนแปลน และแสดงกรอบในหน้า 3D ให้เทียบกับ point cloud |
| **ทิศเปิดประตู** | หาบานประตูที่เปิดค้างอยู่ในสแกน บอกได้ว่าบานพับอยู่ซ้าย/ขวา หรือเป็นบานคู่ และเปิดเข้า/ออกนอกห้อง วาดบานพร้อมเส้นโค้งทิศเปิดบนแปลน, DXF และหน้า 3D (บานที่เปิดค้างไม่ถูกนับเป็นผนังอีกต่อไป) |
| **รูปด้าน (Elevation)** | รูปด้านผนังทุกด้าน มองจากในห้อง ติด key A, B, C… (เรียงตามเข็มนาฬิกาจากทิศเหนือ) บนแปลนให้จับคู่กันได้ มีประตู/หน้าต่าง (พร้อมสัญลักษณ์ฝั่งบานพับ), เส้นบอกขนาดระยะช่องเปิดตามแนวพื้น, ความสูงพื้นถึงฝ้า, ขอบล่าง/ขอบบน, ระยะที่วัดด้วย AR ใกล้ผนังนั้น และจุดสแกนของผิวผนังเป็นพื้นหลัง (สีเทา = ผิวผนัง, สีส้ม = ของที่ติด/อยู่หน้าผนังไม่เกิน 300 มม. เช่น ปลั๊ก ท่อ ตู้) — แตะ key บนแปลนเพื่อเปิดรูปด้านนั้น |
| **แก้ / เพิ่มเอง** | แตะสัญลักษณ์บนแปลนหรือรายการในตาราง เพื่อแก้ประเภท ขนาด (กว้าง สูง ขอบล่าง ระยะจากมุมซ้าย เป็น มม.) ทิศเปิดประตู หรือสลับฝั่งในห้อง; กด **+** แล้วแตะผนังเพื่อเพิ่มประตู/หน้าต่างที่สแกนไม่เจอ รายการที่ป้อนเองจะติดป้าย MANUAL ในไฟล์ส่งออก |
| **ส่งออก** | โมเดล 3D สีจริง GLB / OBJ / PLY (Windows 3D Viewer, Blender, SketchUp, MeshLab), DXF แปลน (AutoCAD), PLY / PTS point cloud (CloudCompare, ReCap → Revit/AutoCAD), OBJ ผนัง 3D (SketchUp, Blender), CSV ตารางระยะ (Excel) — แชร์ผ่าน LINE, Gmail, Drive ได้ทันที |
| **ภาษา** | ไทย / อังกฤษ ตามภาษาของเครื่อง |

### ไฟล์ส่งออกใช้ทำอะไร

| ไฟล์ | เปิดด้วย | ใช้ทำ |
|---|---|---|
| `*_plan.dxf` | AutoCAD, BricsCAD, ZWCAD, LibreCAD | แปลนผนัง + เส้นบอกขนาด (layer `A-WALL`, `A-DIMS`), ประตูพร้อมบานและเส้นโค้งทิศเปิด (`A-DOOR`), หน้าต่าง (`A-GLAZ`), tag (`A-OPEN-TAG`), ตารางประตู-หน้าต่าง รวมคอลัมน์ SWING เช่น `L-IN`, `R-OUT`, `PAIR-IN` (`A-SCHED`), ระยะที่วัด (`A-MEAS`), key รูปด้าน (`A-ELEV-KEY`), จุดสแกนสำหรับลากเส้นทับ (`A-SCAN-SLICE`) หน่วย **มิลลิเมตร** |
| `*_elevations.dxf` | AutoCAD, BricsCAD, ZWCAD, LibreCAD | รูปด้านผนังทุกด้านเรียงกัน พื้น = 0: ผนัง (`A-ELEV-WALL`), ประตู (`A-ELEV-DOOR`), หน้าต่าง (`A-ELEV-GLAZ`), tag (`A-ELEV-TAG`), เส้นบอกขนาด (`A-ELEV-DIMS`), ระยะที่วัด (`A-ELEV-MEAS`), จุดสแกนผิวผนัง (`A-ELEV-SCAN`) และของหน้าผนัง (`A-ELEV-SCAN-FRONT`) ไว้ลากเส้นทับทำ shop drawing งานติดตั้งบนผนัง หน่วย **มิลลิเมตร** |
| `*_model.glb` | Windows 3D Viewer, Blender, SketchUp (importer), เว็บ 3D viewer | โมเดล 3D ผิวสีจริง (Y ชี้ขึ้นตามมาตรฐาน glTF, พื้น = 0) |
| `*_model.obj` / `*_model.ply` | Blender, MeshLab, CloudCompare | โมเดล 3D ผิวสีจริง (สีต่อจุดยอด) |
| `*_points.pts` | Autodesk ReCap → Revit / AutoCAD | point cloud เต็ม ใช้ลากทับทำ shop drawing / ตรวจระยะ |
| `*_points.ply` | CloudCompare, MeshLab, Blender | point cloud สี |
| `*_walls.obj` | SketchUp, Blender, Revit | ผนังเป็นแผ่น 3D สูงพื้นถึงฝ้า เจาะช่องประตู/หน้าต่างแล้ว |
| `*_doors_windows.csv` | Excel, Google Sheets | ตารางประตู-หน้าต่าง: tag, ประเภท, กว้าง, สูง, ขอบล่าง, ขอบบน, ระยะจากมุมซ้าย/ขวา (มม.), บานพับ (`LEFT`/`RIGHT`/`BOTH`), ทิศเปิด (`IN`/`OUT`), ที่มา (`SCAN`/`MANUAL`) |
| `*_measurements.csv` | Excel, Google Sheets | ตารางระยะที่วัด (มม.) พร้อมพิกัดและ dx/dy/dz |

**ทุกไฟล์ของสแกนเดียวกันใช้ระบบพิกัดเดียวกัน** (Z ชี้ขึ้น, พื้น = 0, ผนังหลักขนานแกน X/Y)
จึงซ้อนกันใน CAD ได้พอดี

## อุปกรณ์ที่รองรับ

- Android 7.0 (API 24) ขึ้นไป ที่ [รองรับ ARCore](https://developers.google.com/ar/devices)
- แนะนำรุ่นที่รองรับ **Depth API** (ในรายการเดียวกันระบุ "Supports Depth API") เพื่อได้ point cloud หนาแน่น
- ต้องมี *Google Play Services for AR* (แอปจะพาไปติดตั้งให้อัตโนมัติ)
- มือถือที่ไม่รองรับ ARCore ยังเปิดดู/ส่งออกสแกนเดิมได้ แต่สแกนใหม่ไม่ได้

## ติดตั้ง APK

1. เปิด https://github.com/Banyawa/Scaner/actions → เลือก run ล่าสุดที่เป็นสีเขียว → ในหัวข้อ **Artifacts** โหลด **site-scanner-apk** (ไฟล์ zip ข้างในมี `app-release.apk`)
2. ส่งไฟล์ `.apk` เข้ามือถือ (LINE, Drive, สาย USB) → แตะเปิด → ติดตั้ง (ครั้งแรกต้องอนุญาต *ติดตั้งแอปจากแหล่งที่ไม่รู้จัก*)
3. เปิดแอป → อนุญาตกล้อง → ถ้าเครื่องยังไม่มี *Google Play Services for AR* แอปจะพาไปติดตั้งให้

**อัปเดต:** ทุก build ลงนามด้วย key เดียวกัน (`app/testing.p12`) ติดตั้งทับเวอร์ชันเดิมได้เลย โปรเจกต์และสแกนในเครื่องยังอยู่
เลขเวอร์ชันคือ `0.1.<เลข run ของ CI>` (ดูได้ใน ตั้งค่า → แอป)
build ก่อน run #20 ใช้ key ชั่วคราว ต้องถอนแอปเดิมออกหนึ่งครั้งก่อนลง

`site-scanner-debug-apk` คือ build แบบ debug (ช้ากว่า มี log มากกว่า) ใช้เมื่อต้องการไล่ปัญหาเท่านั้น

**key สำหรับเผยแพร่จริง:** `testing.p12` เป็น key ทดสอบที่ใครก็เห็นได้ ถ้าจะเผยแพร่แอป ให้สร้าง key ส่วนตัวแล้วตั้ง Repository secrets `SIGNING_KEYSTORE_BASE64` (ไฟล์ `.p12` เข้ารหัส base64, alias `sitescanner`) และ `SIGNING_PASSWORD` — CI จะใช้ key นั้นแทนอัตโนมัติ (ต้องถอนแอปเดิมออกหนึ่งครั้งตอนเปลี่ยน key)

## อัดวิดีโอแล้วให้แอปสร้าง 3D เอง

ตั้งแต่เวอร์ชันนี้ การสแกนคือการ **อัดวิดีโอเดินสำรวจ**: ระหว่างกด "เริ่มสแกน" แอปเก็บภาพกล้อง ตำแหน่งกล้อง และ depth ของทุก keyframe ลงเครื่อง (จุดสีฟ้าบนจอบอกแค่ว่ากวาดถึงไหนแล้ว) พอกด **บันทึก** แอปจะ **สร้าง point cloud และโมเดล 3D สีจริงจากวิดีโอที่อัดไว้** โดยใช้ทุกเฟรม ใช้เวลาราว 1 นาที (กด "ทำต่อในพื้นหลัง" ได้ ความคืบหน้าจะขึ้นที่การ์ดสแกน) กด **สร้างโมเดล 3D** ที่การ์ดสแกนเพื่อสร้างใหม่ได้ทุกเมื่อ

ส่งออก **วิดีโอที่อัดไว้ ZIP** ได้จากเมนูส่งออก ข้างในมี:
- `frames/*.jpg` + `frames.jsonl` ภาพและตำแหน่งกล้องทุกเฟรม (+ depth ถ้าเครื่องมี)
- `colmap/` และ `transforms.json` ตำแหน่งกล้องในรูปแบบที่ **COLMAP, RealityCapture, Postshot (Gaussian splatting), nerfstudio** อ่านได้ → ทำโมเดลคุณภาพภาพถ่ายบนคอมได้โดยไม่ต้องคำนวณตำแหน่งกล้องใหม่ (ดู `README.txt` ในไฟล์)

บนคอมใช้ `reconstruct.jar` (artifact `reconstruct-tool` จาก GitHub Actions) สร้างโมเดลจาก ZIP ได้เหมือนในแอป และได้ภาพ preview 3 มุม:

```
java -jar reconstruct.jar recording.zip out/
```

**ถ้าผลสแกนดูไม่รู้เรื่อง** ส่งออก **วิดีโอย่อ ZIP** (ไม่เกิน 20 MB) แล้วอัปโหลดใน GitHub: เปิด repo → `Add file → Upload files` → ลากไฟล์ลงโฟลเดอร์ `samples/` → Commit จะได้ไล่หาสาเหตุจากข้อมูลจริง

## วิธีสแกนให้แม่น

1. สร้างโปรเจกต์ → กด **สแกน** → ขยับมือถือช้า ๆ จนสถานะขึ้น "พร้อม"
2. กดปุ่มกลม **เริ่มสแกน** แล้วเดินช้า ๆ กวาดกล้องไปตามผนัง **ห่างพื้นผิว 1–3 เมตร** (จำนวนจุดบนจอต้องเพิ่มขึ้น)
   (depth แม่นที่สุดในช่วงนี้; ไกลเกิน 4 ม. จะไม่ถูกเก็บ)
3. ให้กล้องเห็น **ผนังช่วงระดับเข่าถึงศีรษะ** ครบทุกด้าน, พื้น และฝ้า — แปลนคำนวณจากช่วงนี้
4. แสงต้องพอ หลีกเลี่ยงกระจก/ผิวมันวาว/ผนังขาวเรียบไม่มีลาย (ติดเทปหรือกระดาษช่วยได้)
5. **ประตู/หน้าต่าง:** ให้กล้องเห็นวงกบทั้งสองข้าง ผนังเหนือช่อง (head) และใต้หน้าต่าง (sill) ชัด ๆ
   **เปิดประตูค้างไว้ประมาณ 30°–150°** และสแกนให้เห็นบานทั้งแผ่น แอปจะบอกทิศเปิดได้
   (ประตูที่ปิดสนิทจะถูกมองเป็นผนัง ส่วนบานที่เปิดจนแนบผนังจะบอกทิศเปิดไม่ได้ ต้องเลือกเอง)
   ความกว้างฝั่งบานพับอาจคลาดได้ไม่กี่ ซม. ผ้าม่าน/มู่ลี่ที่ปิดอยู่ทำให้หน้าต่างถูกมองเป็นผนัง
   ประตู/หน้าต่างที่สแกนไม่เจอ กด **+** ในหน้าแปลนแล้วแตะผนังเพื่อเพิ่มเอง
6. ระยะสำคัญ (ช่องเปิด, ระยะติดตั้ง) ให้ **วัดด้วยปุ่มวัดระยะ** เพิ่ม แล้วตั้งชื่อไว้
   ระยะที่วัดชิดผนัง (ไม่เกิน 20 ซม.) จะแสดงบนรูปด้านของผนังนั้นด้วย
7. **รูปด้าน:** สแกนผนังให้ทั่วตั้งแต่พื้นถึงฝ้า รวมของที่ติดผนัง (ปลั๊ก สวิตช์ ท่อ ตู้แขวน) ให้เห็นชัด
8. กด ✓ บันทึก — ห้องใหญ่/หลายห้องให้แบ่งเป็นหลายสแกน

> ⚠️ **ความแม่นยำ:** ARCore depth บนมือถือทั่วไปคลาดเคลื่อนประมาณ 1–3% ของระยะ
> และสะสมเมื่อเดินไกล เหมาะกับการเก็บข้อมูลหน้างานเบื้องต้นและทำแบบร่าง
> **ระยะวิกฤตต้องตรวจสอบด้วยตลับเมตร/เลเซอร์ก่อนสั่งผลิตเสมอ**

### หลักการทำงานโดยย่อ

1. **Fusion:** ทุก keyframe (ขยับ ≥3 ซม. หรือหมุน ≥3°) ดึง raw depth + confidence + ภาพสี
   → back-project แต่ละ pixel เป็นจุดในโลก → รวมลง voxel grid 1 ซม. แบบถ่วงน้ำหนัก confidence
   (ลด noise; voxel ที่เห็นครั้งเดียวแบบไม่มั่นใจจะถูกตัดตอนบันทึก)
2. **แปลน:** histogram ความสูง → พื้น/ฝ้า; ตัดช่วง 0.3–1.8 ม. เหนือพื้นเป็น occupancy grid 2.5 ซม.;
   หามุมผนังหลักที่ทำให้ projection "คม" ที่สุด; ดึงแนวผนังขนานแกน + RANSAC สำหรับผนังเฉียง;
   ตัดช่วงว่าง >30 ซม. (ประตู); ต่อปลายผนังเข้ามุม
3. **ประตู/หน้าต่าง:** ผนังแต่ละแนว (รวมท่อนที่อยู่แนวเดียวกัน และยืดถึงมุมห้อง) ทำเป็นกริด 4 ซม. ตามแนวผนัง × ความสูง
   หา "รู" ที่ไม่มีจุดบนผิวผนัง แล้วยอมรับเป็นช่องเปิดเมื่อมีหลักฐานว่าเป็นของจริง ไม่ใช่ส่วนที่สแกนไม่ถึง:
   วงกบทึบทั้งสองข้าง + ผนังเหนือช่อง (ประตู/หน้าต่าง) + ผนังใต้ช่อง (หน้าต่าง) หรือเห็นพื้นผิวที่อยู่ลึกเข้าไปผ่านช่อง;
   ตัดทิ้งถ้ามีพื้นผิวขนานผนังอยู่ด้านหน้า (ตู้/เฟอร์นิเจอร์บัง) ; รวมหน้าต่างที่มีเสาแบ่งบาน (mullion) เป็นบานเดียว;
   สุดท้ายปรับขอบให้ละเอียดระดับ ซม. จากจุดสแกนจริงที่ขอบวงกบ/ขอบล่าง/ขอบบน
4. **ทิศเปิดประตู:** รอบประตูแต่ละบาน ลองลากเส้นออกจากวงกบทั้งสองข้าง ทั้งฝั่งในและนอกห้อง ทุกมุม 6°–174°
   (รวมกรณีบานพับอยู่ผิวผนังด้านนอกของผนังหนา) หาเส้นที่มีพื้นผิวสูงต่อเนื่องจากบานพับยาวเท่าความกว้างช่อง
   ถ้าพื้นผิวยาวเลยปลายบานไปตามแนวเดียวกัน (ผนัง/ตู้) จะไม่นับว่าเป็นบาน; บานคู่คือพบบานครึ่งความกว้างจากวงกบทั้งสองข้าง
5. **รูปด้าน:** ผนังแต่ละแนว (ยกเว้นหน้าตู้ที่ถูกนับเป็นผนังสั้น ๆ หน้าผนังจริง) หาฝั่งในห้องจากจุดพื้นที่สแกนได้,
   ฉายจุดสแกนที่อยู่ห่างผิวผนังไม่เกิน 30 ซม. ลงระนาบผนังเป็นกริด 2 ซม. (เก็บระยะยื่นจากผนังไว้แยกสี),
   แล้ววางประตู/หน้าต่าง (รวมที่แก้เอง) และระยะที่วัดด้วย AR ที่อยู่แนวผนังนั้น

## Build จาก source

ต้องมี JDK 17+ และ Android SDK (API 36)

```bash
./gradlew :core:test          # unit test ของ core (ไม่ต้องมี Android SDK)
./gradlew :app:assembleDebug  # ได้ app/build/outputs/apk/debug/app-debug.apk
```

หรือเปิดโฟลเดอร์นี้ด้วย Android Studio แล้วกด Run
GitHub Actions (`.github/workflows/android.yml`) รัน test และ build APK ทุกครั้งที่ push
